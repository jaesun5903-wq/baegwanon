# SAMBA-WAVE 기획 보완사항 검토

- 작성일: 2026-10-05
- 대상: `SAMBA-WAVE 프로젝트 대화정리 및 개발로드맵` 문서와 현재 화면(상품관리, 정책관리)
- 목적: 기존 기획에서 빠졌거나 다시 생각해야 할 부분, 우선순위 정리

> 기존 기획은 기술 구조(작업 큐, 체크포인트, 계정 격리, AutoTune)는 잘 잡혀 있다.
> 하지만 **구매대행만의 영역(통관·세금·법규·마켓 정책·정확한 손익 계산)** 이 거의 빠져 있다.
> 실제로 돈을 잃거나 계정이 정지되는 원인은 대부분 이 영역에서 나온다.

## 1. 반드시 추가해야 할 것 (구매대행 고유 영역)

### 1-1. 통관 / 개인통관고유부호

- 주문 수집 시 **개인통관고유부호를 받고, 이름·전화번호와 일치하는지 검증**한다. (관세청 조회 API 활용)
- **통관 금지·제한 품목 필터**를 둔다. 수집 단계에서 걸러낸다.
  - 식품, 건강기능식품, 의약품
  - KC 인증이 필요한 전기용품·생활용품·어린이제품
  - 전파인증 대상 전자기기
- **면세 한도와 합산과세** 판단 로직
  - 목록통관 / 일반통관 구분
  - 국가별 면세 한도 차이
  - 같은 날 통관되는 주문의 합산과세 위험 경고
- **HS코드(품목분류) → 관세율** 매핑 테이블

### 1-2. 가격 계산식 보정 (중요)

현재 화면 공식:

```text
[상품금액] = [원가] + [마진] + [배송비] + [소싱처 추가 마진] + [관세] + [마켓 수수료]
```

이 방식은 **수수료만큼 마진이 덜 남는다.** 마켓 수수료는 *판매가*에 붙기 때문이다. 다음 공식으로 바꾼다.

```text
판매가 = (원가×환율 + 해외배송비 + 배대지비 + 관부가세 + 국내배송비 + 목표이익)
         ÷ (1 − 마켓수수료율 − 결제수수료율)
```

추가해야 할 비용 항목:

| 항목 | 설명 |
|---|---|
| 환율 | 실시간 환율 + 변동 대비 버퍼(예: +2~3%). 환율이 급변하면 가격 재계산 |
| 배대지 비용 | 실무게와 **부피무게** 중 큰 값 기준 |
| 해외 카드 결제 수수료 | 카드사 해외결제 수수료, 환전 수수료 |
| 소싱처 현지 세금 | Sales Tax 등 |
| 반품·교환 예상 비용 | 반품률 × 평균 반품비 |
| 반올림 규칙 | 10원/100원 단위, 끝자리 900원 등 |

정책을 바꾸기 전에 반드시 **"가격이 바뀌는 상품 N개, 역마진 M개"를 미리보기**로 보여준다.

### 1-3. 배송대행지(배대지) 연동

기존 문서에서 가장 크게 빠진 부분이다. 없으면 주문이 늘수록 수작업이 폭발한다.

- 배대지 신청서 자동 작성 (주문 → 배대지 신청)
- 송장 흐름 추적: **해외 송장 → 배대지 입고 → 출고 → 국내 송장**
- 합배송 / 분할배송 처리
- 배대지 입고 지연, 파손, 오배송 상태 관리
- 실제 청구된 배대지 비용을 주문 손익에 반영

### 1-4. 법규 / 표시 의무

- 통신판매업 신고 정보 관리
- 상품에 **"해외구매대행" 표시**
- **상품정보제공고시** (카테고리별 필수 항목) 자동 채움
- 해외구매대행 **반품비·취소 규정을 상세페이지에 고지**
- 개인정보(통관부호, 주소, 전화번호)
  - 암호화 저장
  - 보관 기간 경과 시 자동 파기
  - 조회 권한 제한 및 조회 기록
- 부가세 신고 방식(대행 수수료로 볼지, 판매로 볼지)은 **세무사와 먼저 정한 뒤** 매출 통계 구조를 맞춘다.

### 1-5. 지식재산권 / 금지어

- **브랜드·상표 금지어 DB**를 만들고 마켓별로 따로 관리한다. 상표권 신고가 쌓이면 스토어가 정지된다.
- AI 상품명 생성 결과도 **반드시 금지어 검사를 거친다.**
- 소싱처 이미지 저작권 위험을 인지하고, 신고 접수 시 빠르게 내릴 수 있는 기능을 둔다.

## 2. 기획에서 다시 생각해 볼 부분

### 2-1. ⚠️ 마켓 다중계정과 대량 등록

- "스마트스토어 20개 계정", "하루 1~3만 개 등록"은 **마켓 운영정책과 충돌할 가능성이 크다.**
  - 네이버·쿠팡 등은 동일인 다수 스토어, 대량 저품질 등록, 중복 상품을 제재한다.
- 개발 전에 확인할 것:
  - 계정마다 실제 별도 사업자가 있는지
  - 마켓 등급별 상품 등록 한도
  - API 호출 한도
- 목표 지표는 "등록 수"보다 **"팔리는 상품 비율"** 로 잡는다.

### 2-2. ⚠️ 마켓 작업은 공식 API로만

마켓 등록·가격·재고·주문은 **Playwright 대신 공식 API**를 사용한다.

| 마켓 | API |
|---|---|
| 네이버 스마트스토어 | 커머스API |
| 쿠팡 | WING Open API |
| 11번가 | 11번가 OpenAPI |
| G마켓·옥션 | ESM+ API |
| 롯데ON, SSG 등 | 각 사 제휴 API |

브라우저 자동화는 **API가 없는 소싱처에만** 사용하고, 약관·요청 간격 제한을 지킨다.

### 2-3. ⚠️ 해외 결제는 반자동으로

- 자동 결제는 사고 시 돈이 바로 나간다.
- 초기에는 **"주문 정보 자동 입력 + 결제 버튼은 사람이 누름"** 방식으로 시작한다.
- 결제 직전 체크:
  - 소싱가·재고 재확인
  - 옵션 일치 확인
  - 역마진이면 차단
  - 통관부호 검증 완료 여부

### 2-4. 멱등성 (중복 실행 방지)

- 마켓 등록, 가격 변경, 결제 요청에 **멱등키(idempotency key)** 를 붙인다.
- 재시도해도 같은 상품이 두 번 등록되거나 두 번 결제되지 않게 한다.
- 기존 `Job` / `JobItem` 구조에 `idempotency_key` 필드를 추가한다.

## 3. 현재 화면 기준 추가 제안

| 화면 | 추가 제안 |
|---|---|
| 상품관리 상단 카드 | 수집/판매 수 외에 **등록실패, 품절, 역마진, 금지어 의심, 오늘 주문** 카드 추가. 클릭하면 해당 목록으로 필터 |
| 상품관리 일괄 버튼 | `마켓삭제`, `강제삭제`, `유형삭제`는 **확인창 + 권한 체크 + 작업 큐 처리 + 되돌리기 기록** 필요. 위험 버튼은 더보기 메뉴 안으로 이동 |
| 정책관리 | 정책 **버전 관리**(변경 전후 비교), **상품 그룹 단위 정책 적용**, 변경 영향 **미리보기** |
| 마켓정책 (수수료 입력) | 수수료를 손으로 입력하지 말고 **마켓별·카테고리별 수수료 테이블**에서 자동으로 불러오기 |
| AI 비용 | **일/월 예산 한도 + 초과 시 자동 중지**, 상품 1개당 비용, 작업별 비용 표시 |
| 매출통계 | 매출보다 **주문별 실제 순이익** 중심. 마켓 정산금 − 실제 구매가 − 실제 배송비 − 실제 관부가세 − 반품비. 예상 마진 vs 실제 마진 비교 |
| 수동등록 / 스토어케어 / SNS | "개발예정" 메뉴는 MVP에서 숨김 |

## 4. 데이터 · 운영 보완

### 4-1. 상품 데이터

- **옵션 매핑 테이블**
  - 사이즈 변환 (예: US 9 → 270)
  - 색상명 번역
  - 옵션별 추가금 반영
- **상세페이지 생성**
  - 이미지 내 외국어 텍스트 번역/제거
  - 마켓 이미지 서버 업로드 (외부 링크 이미지는 마켓에서 막힘)
- **카테고리 매핑**
  - 마켓별 카테고리 코드
  - 카테고리별 필수 고시정보, 인증 필요 여부, 수수료율 연결

### 4-2. 보안

- 마켓 API 키, 소싱 계정 비밀번호 **암호화 저장** (환경변수의 마스터 키로 암호화)
- 관리자 **2단계 인증**
- **감사 로그**: 누가, 언제, 어떤 가격·정책·상품을 바꿨는지 기록
- 직원 권한별로 개인정보 조회 제한

### 4-3. 대용량 데이터

- 가격·재고 이력은 30~50만 상품 기준 금방 수천만 건이 된다.
  - 처음부터 **날짜별 파티션**
  - **보관 기간 정책** (예: 상세 이력 90일, 이후 일 단위 요약)
- 이미지는 오브젝트 스토리지에 저장하고 DB에는 경로만 저장

### 4-4. 속도 제한

- 소싱 계정·마켓 계정별로 **Redis 토큰 버킷** 등으로 요청 속도 제한
- 차단 위험을 줄이고, 한 계정의 문제가 다른 계정에 번지지 않게 한다.

## 5. 개발 순서 제안 (25단계 → MVP 우선)

기존 25단계를 초보자 1인이 순서대로 진행하면 결과물이 나오기까지 너무 오래 걸린다.
**소싱처 1곳 + 마켓 1곳으로 수익 구조부터 검증**한다.

### MVP 1차 — 등록까지

1. 로그인 / 권한 (기본)
2. 소싱처 1곳 상품 수집
3. 상품 DB (상품, 옵션, 이미지)
4. **가격 엔진 (1-2 공식 적용)**
5. 금지어 · 통관 금지 품목 필터
6. 스마트스토어 커머스API로 상품 등록

### MVP 2차 — 주문까지

1. 재고·가격 동기화 (AutoTune 기본)
2. 품절 처리
3. 주문 수집 + 통관부호 검증
4. 반자동 구매 (결제 직전 재확인)
5. 배대지 연동 · 송장 등록
6. 주문별 실제 순이익 계산

### 확장

- 마켓 추가 (쿠팡, 11번가, ESM 등)
- AI 상품명·태그·카테고리 최적화
- HOT / ACTIVE / NORMAL 우선순위
- 대시보드 고도화
- 다중 사업자

### 마지막

- 대량 데이터 성능 테스트
- 서버 배포 및 24시간 운영

## 6. 우선순위 Top 5

1. **가격 공식** — 수수료를 판매가 기준으로 계산, 환율 버퍼, 관부가세 반영
2. **금지어 · 통관 금지 품목 필터**
3. **마켓 공식 API 사용 + 다중계정 정책 확인**
4. **주문 직전 재확인 + 결제 중복 방지(멱등키)**
5. **주문별 실제 순이익 추적**

## 7. 기존 데이터 모델에 추가할 엔티티 (참고)

| 엔티티 | 주요 필드 |
|---|---|
| `PricePolicy` | 버전, 환율 버퍼, 마진율/금액, 최소이익, 반올림 규칙, 적용 상품 그룹 |
| `MarketFeeRate` | 마켓, 카테고리 코드, 수수료율, 적용 시작일 |
| `ExchangeRate` | 통화, 환율, 조회 시각 |
| `HsCode` | HS코드, 관세율, 통관 제한 여부 |
| `BannedKeyword` | 키워드, 유형(상표/통관/마켓금지), 적용 마켓 |
| `ForwarderShipment` | 배대지, 해외 송장, 입고/출고 상태, 무게, 실청구 비용 |
| `CustomsInfo` | 주문, 통관부호(암호화), 검증 결과, 검증 시각 |
| `OrderProfit` | 주문, 정산금, 실구매가, 실배송비, 관부가세, 반품비, 순이익 |
| `AuditLog` | 사용자, 대상, 변경 전/후, 시각 |
